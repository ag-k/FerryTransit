# バージョン別リリースTODO

Web、iOS、Android のリリースに必要な作業をバージョン単位で管理する。各バージョンのファイルは、実装・QA・承認を含むリリースゲートとして扱う。

## 保存場所と命名

- 保存場所: `docs/releases/`
- ファイル名: `v<major>.<minor>.md` または `v<major>.<minor>.<patch>.md`
- 最新TODO: [`v2.5.md`](./v2.5.md)
- リリースノートは従来どおり `docs/reports/` に保存し、TODOファイルからリンクする。

## 運用ルール

1. リリース対象を決めた時点で、バージョンごとのTODOファイルを作る。
2. 共通QAは `AGENTS.md` の「リリースQA」に従い、バージョン固有の機能・データ・移行作業をTODOへ追加する。
3. 完了条件と証跡を確認してからチェックを `[x]` にする。実行していない項目を推測で完了扱いにしない。
4. 対象外の項目は削除せず、`[x] N/A: 理由（承認者）` と記録する。
5. QA後にコード、設定、データ、依存関係を変更した場合は、影響するチェックを `[ ]` に戻して再確認する。
6. 未完了項目を次バージョンへ移すだけで現在のリリースを通さない。延期する場合は、影響と承認者を既知不具合欄へ記録する。
7. 必須チェックがすべて `[x]`、重大・高優先度の未解決不具合が0件、最終承認が記録済みになった時点でのみリリースできる。
8. リリース後はステータス、リリース日時、Git tag、Web URL、App Store / Google Play の公開バージョンを記録し、ファイルを履歴として残す。

## 新規ファイルの最小構成

```markdown
# vX.Y.Z リリースTODO

- ステータス: 準備中
- 対象: Web / iOS / Android
- リリース予定日: 未定
- リリースコミット: 未定
- 担当者: 未定

## リリーススコープ
- [ ] 対象機能と完了条件を確定した

## 実装・データ
- [ ] バージョン固有の実装とデータ更新を完了した

## 共通QA / Web / iOS / Android
- [ ] `AGENTS.md` の必須QAを完了し、証跡を記録した

## 最終判定
- [ ] 全TODO完了、重大・高優先度の未解決不具合0件を確認した
- [ ] Go承認を記録した
```
